# tabpwa kernel / backend rules

## 1. Kernels are independent units

One kernel = **one `.cu` (or `.c`) + one `.so` + one wrapper module**. It is
self-contained and owns its symbols.

- **Allowed**: copy another kernel's source into a new file and adapt it.
- **Forbidden**: a kernel that `#include`s, links against, or calls another
  kernel's symbols; a shared header that couples two kernels; composing two
  backends at runtime; a mode switch that jumps into another kernel's code.
  If two features are needed together (e.g. grouped log-sum **and** a basis
  numerator), both live in the new kernel — not in two kernels glued together.
- Symbol names **do not have to be unique across kernels**: each library is
  loaded independently (cffi `dlopen`, `RTLD_LOCAL`), so a copy may keep the
  original names. What matters is that no kernel *depends* on another and each
  wrapper loads only its own `.so`.
- Count the load-time data each kernel builds itself (amp cache, u-cache,
  Gram): those caches belong to that kernel, not to a shared builder.

## 2. Never modify a working kernel

A kernel that works (tests green, in use) is immutable. Only:

1. **new copy** — new file, new symbols optional, adapted content;
2. **fix a broken kernel** — tests failing / demonstrably wrong (allowed in
   place);
3. **replace** — take a *green* copy and swap it in wholesale, keeping the
   API, and archive the superseded source under `<area>/archive/` (not
   auto-built, kept for rollback).

If a task seems to need editing a working kernel, the design is wrong — say
so instead.

## 3. Bit-identity anchors

Every copy or replacement must carry an **anchor** that pins it to the thing
it replaces, at the settings where the two are the same model:

- fused/replacement kernel vs its predecessor: identical inputs → identical
  output (`np.array_equal` on Q, P, every gradient block, `dnorm`);
- new model vs the old one: the degenerate setting (`N≡1`, `n_index≡0`,
  `resolution_size=1`, one basis row) must be **byte/bit identical**;
- CPU vs `numpy_pwa`: ~1e-15 (both fp64); GPU vs CPU: the documented float2
  amplitude-cache floor (~1e-6..1e-7 relative), never tighter.

Gradients always get a central-difference check through
`Fitter.get_nll` (h=1e-6, tolerance 1e-4 relative) over a sample of
parameters, including any new block.

## 4. Backends

- `@register_backend(name, model=<amplitude-model name>)`; stack decorators
  for aliases; one `"default"` per model.
- `Fitter` asks `backends_for_model(model.name)`; an unknown name fails
  listing the registered ones — never a silent fallback.
- A backend lacking a capability must **raise** with a message that says what
  to use instead (e.g. "pwa_gen numerator not supported by <backend> yet; use
  a CPU backend or n≡1").
- Backends are model-scoped; universal ones pass `model=None`.

## 5. Types

- Kernel coefficients are **real**; basis rows / tables are **complex**.
  Any `i`/`−i` factor belongs to the row, never to a weight.
- Complex parameters split into two **real** slots, names via
  `complex_tail()` — `(magnitude, phase)` semantics, default suffixes `r`/`i`
  (misleading names; they are modulus and phase, `ck = r·e^{iθ}`).
- `Transform` boundary is **real on both sides**: `fd_backward` raises on
  complex inputs and a complex output would give a meaningless gradient for a
  real parameter.
- Name lists (`get_num_name`, `ck_map` combinations) carry the **heads**
  (`x`), not the expanded slots (`xr`, `xi`); consumers expand.
- A kernel-config addition is **optional and default-off**, so configs that do
  not use it stay byte-identical.

## 6. Tests

- Self-contained under `tests/`; fixtures generated by `tests/conftest.py`.
  Nothing outside the repo, nothing committed that the conftest generates.
- One test file per new kernel/model, gated at §3 tolerances, plus the error
  paths (unsupported backend, unknown name, missing dataset).
- Run the full suite before committing; a red suite is never committed.

## 7. Commits

- Tests/checks are a **separate step** from the commit; a commit is a single
  standalone `git commit` (no chaining with test commands).
- Commit message: what changed, the anchor/gate numbers, the measured
  performance, and the kernel-policy case (1/2/3) with the archive path.

## 8. Measurement discipline

- State the harness, event count, `n_proj`, thread count / backend, and
  best-of-N; the machine is often loaded — quote ratios, not single runs.
- Ablate (disable one phase, replace a load with a constant) to find the
  bottleneck before optimising.
- Never claim a speedup without a same-shape before/after; never compare
  different shapes or configs.

## 9. Documentation

- `AGENTS.md` gets a section for a new model/backend: config keys, the ck /
  coefficient rules, backends and their limits, fixtures.
- Design-only documents are labelled "proposed, not implemented".
- Keep design docs inside the repo (`docs/`); never write outside it.

## 10. Regression guards (bugs already paid for)

- `__shfl_down_sync` must be executed by **all lanes**; never inside
  `if (lane == 0)`, and never with a mask that disagrees with the active set.
- A buffer must be written with the **same stride** it is read with
  (`n_uniq` vs `n_unique_bw` produced NaN gradients).
- Frame bookkeeping: bound-transform Jacobians are evaluated at the
  **unbounded** value; uncertainties are propagated through the stage whose
  values are reported. Never pair a value and an error from different stages.
- Benchmark/test data must lie **inside** the interpolation grid
  (`gamma_min + delta·bins`); outside, the table clamps and CPU/GPU diverge.
- The `dNLL/dnorm` chain in `Fitter.get_nll_raw` is keyed by what the backend
  and norm provide — never a hard-coded list of parameter blocks.
- Deriving `coeff` from `m0`/`g0` is a *special case*: any general basis must
  pass explicit coefficients and return `grads["coeff"]`.
